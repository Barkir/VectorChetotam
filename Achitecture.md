# Связь архитектуры с интерфейсами

Архитектуры тесно связана с интерфейсами. Например, добавление плагина должно быть допустимо архитектурой и для этого определяется необходимый интерфейс. Несмотря на то, что внутри некого модуля может быть написано все, что угодна именно его API определяет его функционал.

# Общая архитектура

Для взаимосвязи между модулями выбрана архитектура COM, позволяющая исключить большинство зависимостей между модулями, возложив их на интерфейсы. Также большим плюсом COM является возможность контроля версий интерфейсов и обеспечения обратной совместимости. 

# Архитектура приложения

У приложения есть одно ядро (скорее всего `singleton`), где хранятся указатели на базовые сервисы, без которых приложение в принципе запускаться не может.

## Обработка событий от пользователя и отображение экрана

Событие от пользователя - это `struct Event`. В нем предполагается хранить текущий тип события(`mouseEvent`, `keyEvent`) и информацию для него.
Реализация либо через `union`, либо через `std::variant`.

Для получения Event есть отдельный интерфейс `class InputController`, который определяет методы ` bool pullEvent()`, благодаря которым получается текущий ивент.

Для обработки событий и отрисовки используется N-мерное дерево объектов. Объект - это полностью виртуальный `class AObject`, который объединяет в себе графическую и логическую составляющие.
