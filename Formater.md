# Форматирование кода (clang-format)

Конфигурация стиля находится в файле `.clang-format` в корне проекта.

## Как применить форматтер

Все команды выполняйте из корня проекта. clang-format сам найдёт `.clang-format`.

1. Проверить, какие файлы не соответствуют стилю (ничего не меняет):

```bash
find . -type f \( -name '*.cc' -o -name '*.hh' \) -exec clang-format --dry-run --Werror {} +
```

2. Закоммитить текущее состояние, чтобы изменения было легко просмотреть:

```bash
git add -A && git commit -m "before clang-format"
```

3. Применить форматтер к файлам:

```bash
find . -type f \( -name '*.cc' -o -name '*.hh' \) -exec clang-format -i {} +
```

4. Посмотреть изменения и при необходимости откатить:

```bash
git diff --stat
git checkout -- .
```

## Стиль, который реализует форматтер

**Отступы и ширина**
- Отступ 4 пробела, табы не используются.
- Максимальная длина строки 120 символов.
- Спецификаторы доступа (`public:`, `private:`) находятся на уровне 0, на уровень ниже класса.

**Скобки**
- Allman: открывающая `{` на отдельной строке для классов, структур, перечислений, функций, `namespace`, `if`, `for`, `while`, `switch`, `else`, `catch`.
- Лямбды: `{` остаётся на той же строке, что и сигнатура.
- Пустая функция `{}` разбивается на две строки.

**Пробелы**
- Внутри круглых скобок вызовов и условий: `foo( a, b )`, `if ( x )`. В пустых скобках пробела нет: `foo()`.
- Внутри угловых скобок: `std::unique_ptr< T >`, `static_cast< float >( x )`.
- Без пробела после `template`: `template< typename T >`.
- Внутри квадратных скобок лямбд: `[ this ]`.
- Перед `:` в списке инициализации конструктора есть пробел.
- Перед комментарием в конце строки два пробела не ставятся, используется один: `}; // class X`.

**Выравнивание и переносы**
- Знаки `=` в подряд идущих присваиваниях выравниваются.
- Тело пространства имён начинается с пустой строки.
- Список инициализации конструктора начинается с двоеточия на уровне имени конструктора, без дополнительного отступа.
- Короткие функции (`{ return x; }`) и `if` без `else` в одну строку не пишутся.

**Заголовки**
- Подключения `#include "..."` идут перед `#include <...>`. Порядок внутри групп не сортируется.

## Ограничения

clang-format не умеет ставить пробелы с обеих сторон от `*` и `&`. Он пишет `Type& name` и `Type* ptr`, а в исходниках часто используется `Type & name` и `Type * ptr`. Форматтер приводит такие места к своему виду.

Переносы длинных списков параметров clang-format делает сам, по правилу bin-pack. Иногда выравнивание получается отличным от написанного вручную.
